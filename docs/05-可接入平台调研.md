# 05 · 可接入平台调研（可行性分级）

> 目的：回答「除了现有的 6 个渠道，还能接入哪些 AI 平台」，并给出**可行性分级**与**落地顺序**。
> 采集：2026-09-25，本机（飞牛 NAS，中国大陆家用网络）实地探测 + 公开资料。
> 与 `docs/03-渠道能力矩阵.md` 的分工：03 记录**已接入渠道的实测能力**，本文只做**未接入平台的可行性裁定**。

---

## 1. 判定框架

先明确一件事：**「能接入」有四种完全不同的做法，成本差一个数量级。**

| 方式 | 做法 | 典型成本 | 适用 |
|---|---|---|---|
| **A · 官方 OpenAI 兼容 API** | 配 `base_url` + `api_key`，PoolGate 侧一个「通用上游适配器」全包 | **配置级**（不写代码） | 所有提供 OpenAI 兼容端点的服务商 |
| **B · 官方非兼容 API** | 官方有 API 但形态不同（Gemini 原生、Anthropic 原生、各家私有 JSON） | 一个适配器（半天–1 天） | 官方 API 可用但非 OpenAI 形态 |
| **C · 网页/客户端私有协议逆向** | 驱动网页版或客户端自己的接口（cookie/JWT/设备令牌 + 签名） | 一个适配器（1–3 天，取决于反爬） | 只有网页免费版、没有可用 API 的平台（现有 6 个渠道全走这条） |
| **D · 不建议** | 反爬重（Cloudflare 挑战 / Arkose / 设备指纹）+ ToS 明文禁止 + 封号代价高 | 不划算 | — |

**评估维度**（每个平台都要看）：

1. **免费额度**：网页免费版 / 官方免费额度是否存在，需不需要实名；
2. **凭证形态**：cookie、access token、设备授权流、API key；
3. **反爬与风控**：Cloudflare / Arkose / 各家设备指纹（字节 `sdk-glue`、阿里 `bx-ua`、腾讯 `oneid`）、自研 PoW 签名；
4. **工具调用（function calling）**：**对本文的落地场景是硬指标** —— PoolGate 现在的主要用法是给 Studio / Claude Code 这类 coding agent 当后端，网关 0.4.2 起已支持 tools/tool_calls，但**网页版逆向出来的通道基本都拿不到结构化工具调用**（模型会把工具调用写成文本）；
5. **风险**：违反平台 ToS、账号封禁、必须固定代理 IP。

> **一条先说的结论**：网页免费版「能聊」不等于「能当 agent 后端」。如果目标只是让面板多几个能聊天的模型，C 类可行；
> 如果目标是给 coding agent 用，**优先 A 类**（官方 API + 免费额度），其次是同族的编程助手类 C 类渠道。

## 2. 国外通用聊天平台（网页免费版）

> **一个海外机房出口 IP（实测：netcup GmbH，美国 Virginia；具体地址不写进仓库）**，且没有任何 `*_proxy` 环境变量

**开源逆向项目的维护状态（GitHub 实查）**

- **还在维护**：`lanqian528/chat2api`（ChatGPT，3.8k★）、`xtekky/gpt4free`（66.7k★，2026-09 仍在推）、`HanaokaYuzu/Gemini-API`（3.5k★）
- **已归档/停维**：`acheong08/ChatGPT-to-API`(2023-08)、`acheong08/EdgeGPT`(2023-08)、`dsdanielpark/Bard-API`(2024-04)、`ading2210/poe-api`(2023-09)、`snowby666/poe-api-wrapper`(2025-08)
- **停滞**：`KoushikNavuluri/Claude-API`(2024-08)、`Strvm/meta-ai-api`(2024-11)；Perplexity/Grok/Mistral 的逆向只有 2–130★ 的零散项目

**要点**

1. **完全不值得做**：Claude、Meta AI。不只网页被封，`api.anthropic.com` 从本机也 403 —— 这条出口整组都别谈，除非换干净住宅 IP。
2. **网页逆向对 coding agent 是死路**：所有逆向端点只能吐纯文本，**拿不到 function calling / tool use**；
   而这正是 PoolGate 现在的核心用途（给 Studio / Claude Code 当后端）。ChatGPT/Perplexity/Copilot/Poe 的网页逆向
   即便跑通，也只能当「聊天」用，**不能作为 coding 渠道**。
3. **真正能白嫖又带工具调用的，是官方免费层**：Gemini（`/v1beta/openai/`）、Mistral La Plateforme 免费实验层 ——
   两家都是 OpenAI 兼容 + 支持 tool calling，实测可达。**这两条应该优先立项**，难度低、不用逆向。
   （GitHub Models 原在列，但已 **2026-07-30 全面退役**。）
4. **本机网络本身是最大瓶颈**：机房 IP 直接触发 ChatGPT/Perplexity/Mistral 三家的 Cloudflare 挑战与 Anthropic 的 IP 封禁。
   没有住宅代理的话，可选项只剩 Google / Microsoft / GitHub 这几家对机房 IP 宽容的。
5. **付费兜底**：Poe（`api.poe.com/v1`）与 xAI（符合条件地区 $150/月免费额度）是官方兼容接口里最省事的两条，
   适合当付费补位，而不是逆向目标。

**要点（按落地优先级）**

1. **最划算：GitHub Copilot + Windsurf + AWS Kiro + Google Antigravity** —— 四家都是「免费档 + OAuth/设备流 +
   已有人逆向 + 原生工具调用」，且有 1k–11k★ 的成熟项目可直接借鉴（Copilot 走 device flow；
   Kiro 走 AWS SSO 设备注册且天然多号轮换；Windsurf 的 Cascade gRPC 已被解并有免费档模型清单；
   Antigravity 与 Qoder 同族）。**唯一硬风险是 Antigravity：社区已明确报告 Google 封号/影子封禁**，
   要做就得独立号池 + 降级策略。
2. **最同族、零探索成本：腾讯 CodeBuddy** —— 已有 4 个 `codebuddy2api`，浏览器授权、token 落盘、
   多号轮换与积分避让都现成，而且**与现有 WorkBuddy 渠道共用腾讯系授权**。**建议作为第一个落地的 C 类渠道。**
3. **官方 CLI 路线比逆向更稳**：`gemini-cli` / `qwen-code` / `iflow` 这类官方 CLI 的 OAuth 凭证 + 日额度
   （qwen.ai 2000 req/日）已经有 `*2api` 项目，属于「官方授权的另一种用法」，比逆向网页稳得多。
4. **Cursor 排第三**：免费档价值高，但**项目 README 自己写着可能封号** —— 优先走官方 `cursor-agent` CLI 授权路径，
   逆向只做兜底，单列低优先级号池。
5. **通义灵码价值打折**：免费档只有 50 轮/月，且**没有原生工具调用协议（靠代理层 NLU 模拟）**，
   给 coding agent 用不稳；反倒是「个人专业版限免中」值得先用官方号抢窗口期。
6. **明确放弃**：Cody（已转向 Amp）、Tabnine、Warp、Bolt.new / Lovable / Replit（纯 Web、强风控、无成熟逆向）。
   **BYO-key 类（Zed / Continue / Roo / Cline / Kilo / bolt.diy）根本不需要池化** ——
   让它们把 `base_url` 直接指向 PoolGate 就行，这是最省事的接入方式。
7. 可参考的现成台账：`cockpit-tools`(18.4k★，账号管理)、`sub2api`(42.7k★，订阅拼车)、`9router`。

实测可达性补充：`api2.cursor.sh`、`models.github.ai`、`api.individual.githubcopilot.com`(405)、
`lingma.aliyun.com/lingma/api/v1/chat/completions`(200) 均可直连；`copilot.tencent.com`(401)、
`comate.baidu.com/api/chat`(200) 可达；`api.devin.ai` 与 `ide.iflow.cn` 直连不通。

| 零一万物 | — | — | — | — | 410 | D | 服务已下线 |

**要点**

1. **一个「通用 OpenAI 兼容上游适配器」能一次覆盖约 22 家**（表里标 A 的全部）：它们的请求体、`tools` 字段、
   SSE 分片（`choices[].delta`）完全一致 —— 填 `base_url` + `key` + 模型名即可，**不用为每家写适配器**。
2. **覆盖不到的只有三类**：Anthropic（原生 Messages API，content block 事件流，结构完全不同）、
   Cohere（`v2/chat` 自定义结构）、以及国内厂的**原生签名 API**（混元 TC3-HMAC-SHA256、百度 AK/SK 换 token）
   —— 只有切到它们的「兼容层」才被覆盖。
3. **两家「能覆盖但要留意」**：Perplexity 没有 `/v1/models`，模型名必须手填；Gemini 必须走 `v1beta/openai/` 兼容端点。
4. **可达性出乎意料**：本机（无代理变量）实测这些域名**全部有响应** —— OpenAI/Anthropic/xAI/Groq 回的是 Cloudflare 真实边缘
   （`cf-ray`、`x-openai-proxy-wasm`），说明这台机器的出口能到境外，**表内「直连」成立**。
   注意 DNS 有投毒迹象（`api.openai.com`、`api.x.ai` 的 AAAA 解析落到 `face:b00c:` 即 Facebook 段），但 IPv4 路径正常。
5. **免费额度只能当兜底**：魔搭每日额度、智谱 Flash、OpenRouter `:free`、Cerebras/Groq 免费档、GitHub Models、NVIDIA credits
   都有速率与并发限制，不适合当主力池。
6. **合规顺序**：海外系需海外支付且在大陆使用违反 ToS（有封号风险）；国内系一律需实名。
   风险最低的国内合规组合：**阿里百炼 + 火山方舟 + 硅基流动 + 智谱**。

## 6. PoolGate 侧的接入成本

**方式 A 是唯一「配置级」的**：加一个通用 OpenAI 兼容上游适配器即可一次覆盖第 5 节里所有 OpenAI 兼容服务商。
设计草图（待实现，估半天）：

- 新增 `internal/adapter/openaiup`：`Kind()` 返回动态 kind（如 `openai-<名字>`，模型前缀就是它）；
- `Chat`：POST `<base_url>/chat/completions`，`Authorization: Bearer <key>`，请求体用网关已归一的字段（messages/tools/stream/max_tokens/…），
  响应侧复用现成的通用 OpenAI SSE 解析（`workbuddy/sse.go` 那份就是通用 OpenAI 形态，可提取为共享实现）与 `channel.ParseOpenAIToolCalls`；
- `Models`：GET `<base_url>/models` 拉目录，失败则回退配置里写死的模型清单（不猜、不编造）；
- `Spec`：`Tools` 由配置声明（上游不支持工具就别声明，网关会**明确拒绝**而不是静默丢弃，见 0.4.2）、`SSEOnly=true`、`CheckinCap=false`；
- 装配：`store.Settings` 加 `Providers []ProviderConfig{Name, BaseURL, APIKey, Models, SupportsTools}`，启动时逐个 `registry.Register(...)`
  —— 面板的渠道列表本来就遍历 `registry.All()`，新渠道**自动出现在面板里**，只是把「授权」按钮换成「用配置的 API Key」；
- 凭证：直接用配置里的 key（不需要 OAuth 登录流程），但照样进池 —— 多 key 可轮换、可冷却。

**方式 C 的成本**：每个平台一个适配器 = 请求体构造 + SSE/帧归一化 + 能力声明（`internal/channel` 契约很薄，
现有 6 个渠道的适配器都是这个形状）。**难点不在框架，在反爬与协议** —— 有公开逆向项目可抄的，难度骤降。

## 7. 落地建议（按性价比排序）

### 第 0 步 —— 通用 OpenAI 兼容上游适配器（**不写渠道，收益最大**）

半天工作量，一次覆盖第 5 节里标 A 的约 22 家：**豆包（火山方舟）、GPT（OpenAI）、Gemini、DeepSeek、Kimi、智谱、
通义（百炼兼容模式）、混元、千帆、MiniMax、硅基流动、魔搭、OpenRouter、Groq、Together、Fireworks、Cerebras、
xAI、Mistral、NVIDIA NIM** 等。这是「让面板立刻多出几十个模型」的唯一低成本路径。
（设计要点见第 6 节；`Tools` 由配置声明，上游不支持工具就别声明 —— 网关会明确拒绝，不会静默丢弃。）

### 第 1 步 —— 腾讯 CodeBuddy（同族 C 类里第一个真渠道）

理由：已有 4 个开源 `codebuddy2api`（浏览器授权 + token 落盘 + 多号轮换 + 积分避让都现成）；
**与现有 WorkBuddy 渠道共用腾讯系授权**，工程上几乎零探索成本；支持工具调用 → 能直接给 Studio / Claude Code 用。

### 第 2 步 —— 同族四家（挑你手上有账号的做）

| 渠道 | 参考项目 | 免费档 |
|---|---|---|
| GitHub Copilot | `ericc-ch/copilot-api`(4.1k★) | Copilot Free（AI credits 计量） |
| Windsurf | `dwgx/WindsurfAPI`(3k★) | Free：仅开源模型（glm/kimi/qwen/gemini-flash） |

| gemini-cli / qwen-code / iflow | `geminicli2api`(591★)、`qwen-code-oai-proxy`、`iflow2api` | Gemini OAuth 日额度；qwen.ai 2000 req/日 |

### 第 3 步 —— Anthropic 原生适配器（B 类）

技术上就是「把 PoolGate 现成的 Anthropic 归一化反着用一遍」，不难；但**本机出口 IP 被 Anthropic 直接 403**，
要先把出网换成干净 IP 才谈得上。

### 观察名单（有风险 / 价值打折）

- **Google Antigravity**：免费档大（gemini-3.1-pro/opus），但**社区已报告 Google 封号/影子封禁** → 要做必须独立号池 + 降级策略。
- **Cursor**：免费档价值高，但**项目 README 自认可能封号** → 优先官方 `cursor-agent` CLI 授权，逆向只做兜底。
- **通义灵码**：50 轮/月，且**没有原生工具调用协议**（靠代理层 NLU 模拟）→ 给 coding agent 用不稳；可先用它的个人专业版限免窗口。

### 明确不做

- **逆向国外聊天网页版**（ChatGPT / Perplexity / Copilot 网页 / Poe）：本机是机房 IP，Cloudflare 直接挑战；
  就算跑通**逆向端点也拿不到工具调用** → 对 coding agent 无用。要白嫖就用它们的官方免费层
  （Gemini `/v1beta/openai/`、Mistral La Plateforme、GitHub Models，三家都是 OpenAI 兼容 + 支持 tool calling）。
- **Cody / Tabnine / Warp / Bolt.new / Lovable / Replit**：无成熟逆向项目 + 强风控。
- **文心快码 Comate**：国内大厂里唯一零公开逆向先例的，不建议投入。
- **BYO-key 工具**（Zed / Continue / Roo / Cline / Kilo / bolt.diy）：**根本不需要池化** —— 把它们的 `base_url`
  指向 PoolGate 就是最省事的接入方式。

### 开工前必须先解决的两条硬前提

1. **出网 IP**：本机出口是 netcup 机房 IP；Cloudflare 系（ChatGPT/Perplexity/Mistral 网页）与 Anthropic 直接拒绝。
   要接国外渠道，先解决住宅/家宽出口，否则只能做国内 + 官方 API。
2. **工具调用**：任何渠道进池子前先确认它**能不能给结构化 `tool_calls`** —— 拿不到就只能当聊天用，
   不能给 coding agent 当后端（这正是 0.4.2 刚在 PoolGate 侧打通的那条链路）。

## 8. 合规与风险边界

- 方式 C 全部**依赖逆向平台私有接口**，多数平台的用户协议禁止「自动化访问 / 共享账号 / 转售额度」；
  与本项目现有 6 个渠道同性质 —— 用于个人自用与已有渠道一致，但**不要在公开场合宣传成「白嫖 xx」**，也别拿它做对外服务。
- 网页逆向的通道**受平台改版直接影响**（千问办公就是活例子：上游一加闸门，渠道立刻不可用）。
  这也是 `docs/03` 把它们标 Paused 而非删除的原因 —— 架构上「摘掉一个渠道」必须是分钟级操作。
- 需要固定代理 IP 的平台（Cloudflare 风控类），在 NAS 上还要额外稳定出网方案，属于**隐性运维成本**，评估时别只算开发时间。

### 结论

1. **免费档能碰到旗舰的只有两条路**：**阿里百炼的 `qwen3.8-max`**（100 万 token/模型、90 天）和
   **Gemini CLI 的 OAuth（Gemini 3 含 pro，1000–1500 请求/天）**。注意这俩不是同一件事 ——
   **Gemini 的 HTTP API 免费档不给 Pro**（3.1 Pro Preview 明写「Not available」，只给 3.8 Flash），
   免费的 Pro 只能从 **Gemini CLI / Code Assist 那条 OAuth 路**拿。
2. **AWS Kiro Free 是能力天花板（Claude Sonnet 4.5）但接不进网关** —— 它没有官方对外 API，
   要接只能逆向 IDE 协议（好在有 `kiro-gateway` 2.3k★ 现成项目），属于工程投入最大的一条。
3. **免费档只给中小模型、别抱期望**：Groq、SambaNova、智谱 Flash、硅基流动、OpenRouter `:free`
   全是开源权重或 Flash 级；**Cerebras 没有永久免费档**；**GitHub Models 已于 2026-07-30 全面退役**；
   Copilot Free / Windsurf Free / Cursor Hobby **不给具体模型、也没有对外 API**，接不了网关。
4. **综合「免费 + 强 + 能调工具 + 门槛低」前三名**：
   ① **Google 免费层（Gemini 3.8 Flash，走通用适配器）** —— 免 token 费、账号即可、tools 齐全，无争议第一；

   ③ **OpenRouter `:free`** —— 登录即用、模型多、OpenAI 兼容，最适合当网关的多路兜底（充值 $10 后 RPD 从 50 提到 1000）。
