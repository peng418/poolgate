设计约束（硬性）

这些不是风格偏好，是验收项
状态三重表达图标 + 文字 + 颜色齐备，色觉障碍下仍可辨（原型已如此实现）
判据可见面板上明确写出「收到内容才算通过」，不让人以为在看状态码
失败必带原因任何 error 行都必须有 kind + 上游原话，禁止空白
来源标注能力位/上下文窗口标「上游 / 本地 / 未知」，未知不猜数字
图表可替代每个图都有「表格视图」，图例与直标可见（不靠颜色单独承载身份）
数字对齐金额/延迟/计数用等宽数字，列右对齐
危险可逆危险操作二次确认并写明后果；配置改动可回滚

响应式

手机竖屏至少要能看状态、开关账号

窗口缩到 820px 以下时，左侧导航折叠为顶部横向滚动条，卡片栅格降为单列， 宽表格改为卡片内横向滚动、按钮不换行 —— 页面本身不产生横向滚动。 账号页与总览页是手机端的主要使用场景（看余额、看告警、开关账号）； 登录页在 900px 以下收为单列，左侧说明落到表单上方。

渲染产物见 shots/（7 屏 × 明暗 + 登录页移动端）， 用 node shoot.mjs 可重现。 已知取舍：移动端表格采用卡片内横滚而非堆叠卡片，实现阶段若嫌窄可改为「每账号一张堆叠卡」。

8 · 接入源

登录式渠道 + API Key 式来源，一张表管完

统一入口（一个地址 + 一个 key 调所有模型）· 两类来源混排 · 状态三重表达 · 额度列区分余额/配额/限速

9 · 添加接入源

两步把新来源接进来

选类型（登录授权式 / API Key 式）→ 填参数（预设模板 + 从上游拉模型清单 + 工具调用能力）→ 连通性测试（鉴权 / 目录 / 工具调用 / 延迟）后保存
